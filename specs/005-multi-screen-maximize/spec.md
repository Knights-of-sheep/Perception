# Feature Specification: Multi-Screen Maximize

**Feature Branch**: `005-multi-screen-maximize`

**Created**: 2026-08-28

**Status**: Draft

**Input**: User description: "确保主界面在多屏幕情况下的任何一个屏幕上都可以最大化成功，当前情况是，将主界面拖到另一个屏幕后，点击最大化，窗口却看不到了，很奇怪。"

## Session 2026-08-29（修订记录）

- 缺陷复核：US1–US3 实现（tasks T001–T016）后实测，副屏最大化仍"窗口消失"。根因：`WM_GETMINMAXINFO` 的 `ptMaxPosition` 被填入目标屏工作区的**虚拟桌面绝对坐标**，而 Windows `MINMAXINFO` 语义为**相对目标显示器左上角**的坐标（主屏原点恰为 0 故正常，副屏在主屏右侧/左侧/上方时被推到屏外）。修复：几何层输出"工作区尺寸 + 相对目标屏左上角的偏移"（research R6 / contracts §2 / tasks T017）。行为验收不变（FR-001~006 均以"完整可见"为准）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 任意屏幕最大化成功 (Priority: P1)

用户将主界面拖到另一块屏幕后，点击"最大化"按钮，窗口必须在当前所在的这块屏幕上完整、清晰地最大化——不能出现"窗口消失"或跑到屏幕外的现象。无论用户当前使用哪块屏幕（主屏或副屏），最大化行为都一致且可靠。

**Why this priority**: 这是用户报告的直接影响工作的缺陷：多屏用户拖拽窗口后点击最大化，窗口直接不可见，主界面无法继续使用。修复该缺陷是所有多屏场景正常工作的基础。

**Independent Test**: 在双屏扩展模式下，将主界面拖到副屏并点击最大化，可独立验证窗口在副屏完整可见；无需其他功能配合即可交付价值。

**Acceptance Scenarios**:

1. **Given** 双屏扩展模式（主屏 + 副屏）且主界面位于副屏，**When** 用户点击"最大化"按钮，**Then** 主界面在副屏的工作区内最大化，窗口完整可见、不超出屏幕边界
2. **Given** 主界面位于主屏，**When** 用户点击"最大化"按钮，**Then** 主界面在主屏的工作区内正常最大化
3. **Given** 任意 ≥2 屏幕布局（副屏位于主屏左/右/上方等不对称排列），**When** 用户从任一屏幕触发最大化，**Then** 窗口均在其当前所在屏幕最大化，且完整可见

---

### User Story 2 - 最大化状态可正确恢复 (Priority: P1)

用户将主界面在任意屏幕最大化后，再点击"恢复"按钮，窗口应回到最大化前的位置与尺寸，并且仍然停留在原来的那块屏幕上——不能跳到别的屏幕，更不能跑到屏幕外。

**Why this priority**: 最大化/恢复是对称的核心交互；恢复出错会让用户在"最大化的窗口"与"原位置窗口"之间无法可靠往返，与 US1 一并构成该缺陷的完整验收。

**Independent Test**: 在副屏上将窗口从普通状态→最大化→恢复，可独立验证窗口回到副屏上的原位置与尺寸。

**Acceptance Scenarios**:

1. **Given** 主界面在副屏以普通尺寸显示，**When** 用户最大化后再点击恢复，**Then** 窗口回到最大化前的位置与尺寸，且仍位于副屏
2. **Given** 主界面在副屏最大化，**When** 用户恢复后再次最大化，**Then** 第二次最大化结果与第一次一致（窗口完整可见、不漂移）
3. **Given** 窗口在任一屏幕最大化，**When** 用户恢复，**Then** 窗口不出现于屏幕边界之外或不可见区域

---

### User Story 3 - 显示配置变化后仍可最大化 (Priority: P2)

用户调整显示器分辨率、连接或断开外接显示器之后，再点击"最大化"按钮，窗口仍应在其当前所在屏幕上完整可见地最大化，绝不允许出现"窗口消失、无法找回"的情况。

**Why this priority**: 显示配置变化是多屏用户常见操作，也是"窗口消失"类缺陷的高发场景；其概率低于普通拖拽场景，故列为 P2。

**Independent Test**: 在双屏环境下调整副屏分辨率或断开/重连显示器后触发最大化，可独立验证窗口仍然可见。

**Acceptance Scenarios**:

1. **Given** 窗口已最大化在某块屏幕，**When** 该屏幕分辨率发生变化，**Then** 窗口仍完整可见，不超出新的工作区边界
2. **Given** 窗口位于副屏，**When** 副屏被断开连接，**Then** 主界面在剩余屏幕上仍可正常显示与最大化（不落入不可见区域）
3. **Given** 不同屏幕使用不同的缩放比例（DPI），**When** 用户在主界面所在屏幕触发最大化，**Then** 窗口完整可见、不超出该屏幕边界

---

### Edge Cases

- 窗口部分跨越屏幕边界（如同时压在两块屏幕交界处）时触发最大化：按窗口主体所在的屏幕执行最大化
- 最大化后其所在显示器被断开：窗口应回落到剩余可见屏幕（与操作系统窗口行为一致），不得保持不可见
- 不对称多屏排列（副屏在主屏左/上/斜向）：最大化方向与所在屏幕工作区一致，不依赖主屏位置假设
- 多屏幕 DPI 不同：最大化几何按所在屏幕工作区计算，不因缩放差异导致超出边界
- 连续多次"最大化→恢复"往返：每次恢复结果一致，无累计漂移

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在用户将主界面拖至任意屏幕后点击"最大化"时，使窗口在该屏幕的可见工作区内最大化（完整可见，不超出屏幕边界）
- **FR-002**: 系统 MUST 支持在主屏与任意副屏上触发最大化，行为效果一致（不依赖主屏位置假设）
- **FR-003**: 系统 MUST 在最大化前保存窗口的位置与尺寸，恢复时还原到最大化前的位置与尺寸，且窗口仍停留在最大化前所在的屏幕
- **FR-004**: 系统 MUST 在窗口跨越多个屏幕边界时，按窗口主体所在的屏幕执行最大化
- **FR-005**: 系统 MUST 在显示配置变化（分辨率调整、显示器连接/断开、DPI 变化）后，最大化操作仍产生可见结果，不得导致窗口位于屏幕外且无法找回
- **FR-006**: 系统 MUST 保证"最大化→恢复"可反复往返，每次恢复结果一致，无位置或尺寸的累计漂移

### Key Entities *(include if feature involves data)*

本功能为窗口行为修复，不涉及数据实体。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 ≥2 屏幕（扩展模式）下，从任意屏幕触发最大化，窗口在 100% 的测试场景中完整可见（窗口位置与尺寸核对或截图核对）
- **SC-002**: "最大化→恢复"往返操作后，窗口位置与尺寸与最大化前一致，在 100% 的测试用例中通过（位置与尺寸核对）
- **SC-003**: 显示配置变化（分辨率/连接/断开/混合 DPI）后触发最大化，窗口在 100% 的测试场景中保持完整可见，无"窗口消失"现象
- **SC-004**: 修复后，主界面原有功能（菜单、Dock 布局、面板、主题切换等）回归测试 100% 通过，无新增缺陷

## Assumptions

- 目标环境为 Windows 多屏扩展模式（克隆/镜像模式不做独立验证）
- "最大化"沿用现有无边框主界面的"最大化/恢复"按钮语义，不改变无边框设计与按钮交互方式
- 最大化指在窗口当前所在屏幕的工作区内铺满（不遮挡任务栏，与操作系统最大化行为一致）
- 显示配置热变更（如拔掉显示器）后的回落行为与操作系统默认窗口行为一致即可，不要求记忆已断开屏幕
- 本功能为行为修复，不涉及新的视觉设计，无对应 mockup（现有 mockups 为图标集，与本功能无关）
