# Quickstart: Multi-Screen Maximize — 验证指南

**Branch**: `005-multi-screen-maximize` | **Date**: 2026-08-28

本指南提供端到端验证场景，证明多屏最大化功能按 spec 工作。实现细节见 `plan.md` / `tasks.md`；几何契约见 `contracts/window-maximize-contract.md`。

## 1. 前置条件

- Windows 10/11 桌面，**双屏扩展模式**（副屏可位于主屏左侧/右侧/上方等任意排列）
- VS2022（MSVC）+ Qt 5.15.2（MSVC 2019 64-bit）+ CMake + Ninja
- 仓库根目录可执行构建脚本 `scripts/build.ps1`（GUI 路径已固化默认 Qt/VTK 目录）

## 2. 构建与单测

```powershell
# 构建 GUI 层 + 运行 C++ 单测
.\scripts\build.ps1 -Gui -UnitTests -Config Debug

# 仅运行单测（构建已存在时）
ctest --test-dir build -C Debug --output-on-failure
```

**预期**:

- 构建成功，无新增编译错误
- `ctest` 全部通过，**包括新增 `window_geometry_test`**（目标屏解析/最大化几何/负坐标/恢复几何用例）

## 3. 手动多屏验证场景

> 对应 spec SC-001..003 与 US1/US2/US3 验收场景。逐项执行并核对"预期结果"。

### 3.1 US1 — 任意屏幕最大化成功

| # | 步骤 | 预期结果 |
|---|------|----------|
| 1 | 将主界面从主屏拖到副屏（完整位于副屏） | 窗口完整显示在副屏 |
| 2 | 点击标题栏"最大化"按钮 | 窗口在**副屏**工作区内最大化，完整可见、不超出边界、不覆盖任务栏（不出现"窗口消失"） |
| 3 | 恢复后拖回主屏，再点击最大化 | 窗口在**主屏**工作区内正常最大化 |
| 4 | 将窗口拖到主屏与副屏边界（同时跨两屏）后最大化 | 按窗口主体所在屏最大化（FR-004） |

### 3.2 US2 — 最大化状态可正确恢复

| # | 步骤 | 预期结果 |
|---|------|----------|
| 1 | 在副屏将窗口最大化（见 3.1） | 最大化正常 |
| 2 | 点击"恢复"按钮 | 窗口回到最大化前的位置与尺寸，**仍位于副屏**，不跳屏、不越界（FR-003） |
| 3 | 连续执行"最大化→恢复"3 次 | 每次恢复位置尺寸一致，无累计漂移（FR-006） |

### 3.3 US3 — 显示配置变化后仍可最大化

| # | 步骤 | 预期结果 |
|---|------|----------|
| 1 | 副屏分辨率调低后，在副屏最大化 | 窗口按新工作区完整可见（不越界） |
| 2 | 窗口在副屏最大化时断开副屏 | 窗口回落到主屏可见区域（不保持不可见，FR-005） |
| 3 | 两块屏缩放比不同（如 100% 与 150%）时，分别在各屏最大化 | 窗口均完整可见、不超出所在屏边界（FR-006） |

## 4. 回归检查（SC-004）

- 单测全绿（第 2 节）
- 主界面原有功能抽查：菜单、Dock 布局与拖拽、面板（边框随主题）、PyShell、主题切换、子窗口创建/布局、文件拖放——行为与修复前一致
- 最大化/恢复按钮、标题栏双击最大化两条入口行为一致
