# Feature Specification: 子窗口布局管理

**Feature Branch**: `004-dock-layout-manager`

**Created**: 2026-08-28

**Status**: Draft

**Input**: User description: "增加子窗口布局管理功能，支持设置按行、按列、grid排列，支持设置最大行、最大列、保持相同宽高等属性。"

## Clarifications

### Session 2026-08-28

- Q: 布局管理作用的"子窗口"指哪些窗口？ → A: 主窗口中央区域内用于渲染各种图形/曲线的视图子窗口（未来会有多个）；**不含**属性面板、数据面板、PyShell 窗口等侧边/底部可停靠面板
- Q: 本次交付范围除布局管理外，是否包含子窗口创建能力？创建入口有哪些？ → A: 包含；子窗口可通过 PyShell 中的 Python 命令创建，也可通过主窗口菜单栏创建
- Q: 布局管理（排列模式、最大行/列、相同宽高）是否也需要 Python 命令支持？ → A: 不需要；布局管理仅通过 UI 设置界面操作，不提供 Python 命令接口（PyShell Python 命令仅用于创建子窗口）
- Q: 多个子窗口排列时对视觉与视图能力有哪些要求？ → A: 子窗口之间保留一定间隙；子窗口支持最大化（选中子窗口放大占满整个中央区域）与全屏（选中子窗口放大占满整个主窗口含属性/数据/PyShell 面板区域）；每个子窗口均无 Qt 自带标题栏
- Q: 子窗口边框线条如何保证可见？ → A: 边框始终使用强调色（accent），未选中与选中均为强调色边框，选中子窗口的边框加粗；任何时候边框都醒目可辨（FR-015）
- Q: "优先行排/优先列排"在 layout settings 页面以什么形式展示？ → A: 分段按钮组（三个可选中按钮：网格/优先行排/优先列排，并排显示，点击即切换）（FR-011）
- Q: layout settings 对话框标题栏风格？ → A: 与其他对话框一致的无边框自定义标题栏（图标+标题+关闭按钮，可拖拽移动）（FR-011）
- Q: 数据集/属性/PyShell 面板的外边框采用什么样式？ → A: 三个面板均提供 2px 独立外边框，颜色为当前主题边框色（@border@，深色主题浅灰、浅色主题深灰，随主题自动切换），与子窗口边框宽度统一（FR-023 / SC-014）
- Q: 面板的"内部边框"指什么？ → A: 面板内部标题栏底部分隔线与内容子区域（数据树/属性网格/PyShell 输入输出区）间的分隔线，均为 1px 主题边框色，形成"外 2px + 内 1px"的边框层级（FR-024 / SC-015）
- Q: 拆分 MainWindow.cpp 采用什么方案？ → A: 文件级拆分 + 辅助类独立：MainWindow 类保持不变；DockTitleBar/DockDragOverlay/SashHighlight/NoFocusRectDockStyle/FramelessDialog/ThemedFileDialog 等辅助类移出到独立 .h/.cpp；MainWindow 成员函数按功能域（Dock 布局与拖拽/中央区子窗口/日志/文件/主题/标题栏与窗口控制/菜单动作工具栏）分散到多个 .cpp（FR-025 / SC-016）
- Q: 拆分后的验收标准如何量化？ → A: 拆分后 MainWindow.cpp 不超过 400 行，其他文件按功能域自然划分（单文件不超过 400 行）；行为严格不变（无功能增删）；构建配置同步更新，完整构建 + 现有测试全部通过（SC-016 / SC-017）

### Session 2026-08-29

- Q: 菜单栏"新建子窗口"与 PyShell 创建命令是什么关系？ → A: 创建子窗口必须通过命令行实现，命令层是唯一实现路径；即便从菜单栏点击"新建子窗口"，也必须构造并触发同一 Python 命令执行（禁止绕过命令层直接调用 C++ 入口）；命令文本 MUST 在 PyShell 回显，`create_window` 的返回值（窗口 id 字符串）MUST 在 PyShell 打印（FR-002 / FR-027 / SC-018）
- Q: `create_window` 的返回值语义？ → A: `create_window(title: str = "") -> str`，返回新建子窗口的 **id**（`"Plot_"` + 全局递增序号，如 `Plot_1`）；`title` 缺省（或空白）时 title = id（窗口标题显示 id），传入 title 时窗口标题显示 title；参数类型错误抛 `TypeError`（REPL 展示 traceback），宿主未连接返回 `None` 不崩溃。此修订取代此前"标题统一 plot_ 小写、忽略入参 title"的表述（2026-08-29 用户反馈）
- Q: Grid 布局下能否设置优先行/优先列？ → A: 可以。Grid 模式的布局设置中显示"Priority"radio 组（By row / By column），无约束时决定比例网格的填充方向（Row = FR-004 网格，Column = FR-005 转置）；By Row / By Column 模式保持语义不变。该 radio 仅 Grid 模式显示（2026-08-29 用户反馈）
- Q: 弹窗风格是否要求统一？ → A: 所有应用弹窗（对话框/消息框/文件对话框）MUST 使用无边框自定义标题栏（图标+标题+关闭按钮，可拖拽移动），禁止系统原生标题栏；共享工厂 `src/ui/dialog_title_bar.h` 保证各弹窗一致，条款已写入宪法「技术栈约束 · GUI」2.0.0（2026-08-29 用户反馈）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 创建子窗口：Python 命令与菜单双入口 (Priority: P1)

用户可以通过两种方式创建新的渲染子窗口：在 PyShell 窗口中执行 Python 命令（如 `create_window("曲线图")`），或通过主窗口菜单栏的"新建子窗口"菜单项。两种方式均经命令行执行：菜单栏点击同样触发同一 `create_window` Python 命令（命令文本在 PyShell 回显、返回值打印），不绕过命令层。创建成功后，新子窗口出现在中央区域并立即加入当前布局排列。新子窗口内部为空的渲染视图（占位内容），具体图形/曲线渲染内容由后续功能接入。

**Why this priority**: 创建子窗口是布局管理的作用对象来源——没有创建入口，布局功能无窗口可排；用户明确要求双入口，是本次交付的前提能力，优先于其他故事。

**Independent Test**: 在 PyShell 中执行创建命令并观察中央区域出现新子窗口；再通过菜单栏创建，对比两者行为一致；创建多个子窗口验证参与布局排列。

**Acceptance Scenarios**:

1. **Given** PyShell 窗口已打开，**When** 用户执行创建子窗口的 Python 命令，**Then** 中央区域出现一个新的渲染子窗口，并立即按当前布局模式参与排列
2. **Given** 主窗口菜单栏可见，**When** 用户点击"新建子窗口"菜单项，**Then** 内部触发同一 `create_window` Python 命令执行（命令文本在 PyShell 输出区回显、返回值打印），新增子窗口并参与当前布局排列
3. **Given** 用户连续创建多个子窗口（如 5 个），**When** 查看中央区域，**Then** 所有子窗口按当前布局模式正确排列（网格模式下自动换行）
4. **Given** 新子窗口内部尚无渲染内容，**When** 用户查看该子窗口，**Then** 显示清晰的占位内容，不报错、不崩溃
5. **Given** 用户通过菜单栏或 PyShell 创建子窗口，**When** 查看 PyShell 输出区，**Then** 回显所执行的 `create_window` 命令文本，并打印函数返回值（新建子窗口的 id，如 `'Plot_1'`；参数类型错误展示 TypeError traceback）

### User Story 2 - 一键切换排列模式：按行 / 按列 / 网格 (Priority: P1)

用户通过统一的布局设置入口（如"视图"菜单下的"布局…"）选择排列模式：**按行**（按行优先的保持比例网格，如 2 个 → 2×1、5 个 → 3×2）、**按列**（按列优先的保持比例网格，即优先行的转置，如 2 个 → 1×2、5 个 → 2×3）或**网格**（默认行优先比例网格）。选择后，中央区域内所有已打开的子窗口立即按新模式重排，相邻子窗口之间保留均匀间隙，渲染内容与视图状态不丢失。

**Why this priority**: 三种排列模式是本次功能的核心，用户明确列出的第一项能力；仅实现此故事即可构成可演示的 MVP，独立可交付。

**Independent Test**: 在中央区域准备至少 2 个子窗口，依次切换三种模式，观察子窗口重排结果并截图比对；验证切换前后各子窗口渲染内容与视图状态（缩放、视角、选中数据）一致。

**Acceptance Scenarios**:

1. **Given** 程序已启动且中央区域至少 2 个子窗口已打开，**When** 用户选择"按行"排列，**Then** 所有子窗口按行优先的比例网格排列（如 2 个 → 2 行 1 列、5 个 → 3 行 2 列）、互不重叠、完整可见
2. **Given** 当前为按行排列，**When** 用户选择"按列"排列，**Then** 所有子窗口按列优先的比例网格排列（如 2 个 → 1 行 2 列、5 个 → 2 行 3 列）
3. **Given** 任意排列模式，**When** 用户选择"网格"排列，**Then** 子窗口按矩阵网格排布，列数遵循用户设置的最大列数（未设置时按可用宽度自动计算）
4. **Given** 用户在任一子窗口内进行了操作（如缩放、旋转视角、选中数据），**When** 切换排列模式，**Then** 子窗口渲染内容与视图状态完整保留

---

### User Story 3 - 设置最大行 / 最大列约束 (Priority: P1)

布局设置中提供"最大列数"与"最大行数"输入（取值范围 1–10 的整数）。网格模式下，子窗口数超过最大列数时自动换行；超过最大行数时自动换列。用户调整约束后网格立即重排。

**Why this priority**: 最大行/最大列是用户明确要求的第二项能力，也是网格布局的核心控制参数，与排列模式构成完整的最小闭环。

**Independent Test**: 在中央区域打开 5 个子窗口，分别将最大列数设为 2、最大行数设为 2，观察网格行/列数与约束一致；输入非法值验证提示行为。

**Acceptance Scenarios**:

1. **Given** 网格模式且最大列数设为 2，**When** 有 5 个子窗口打开，**Then** 子窗口排成 3 行 2 列（末行 1 个），任何一行不超过 2 列
2. **Given** 网格模式且最大行数设为 2，**When** 有 5 个子窗口打开，**Then** 子窗口排成 2 行 3 列（末列 1 个），任何一列不超过 2 行
3. **Given** 最大行与最大列同时设为 2，**When** 有 5 个子窗口打开，**Then** 4 个子窗口填满 2×2 网格，第 5 个子窗口保持可访问（不丢失、不遮挡）
4. **Given** 用户输入非法约束值（0、负数、非数字），**When** 提交设置，**Then** 显示明确提示并恢复上次有效值

---

### User Story 4 - 保持相同宽高 (Priority: P2)

布局设置中提供"保持相同宽高"开关。开启后，同一排列中的全部子窗口宽度与高度统一为一致尺寸；关闭后恢复各子窗口原有尺寸。开启状态下用户拉伸窗口时，所有子窗口同步等比变化，始终保持宽高一致。

**Why this priority**: 用户明确要求的第三项属性，依赖排列模式与约束的布局基础；在行/列/网格任一模式下均可叠加生效，独立可测。

**Independent Test**: 开启开关后比较各子窗口尺寸截图；关闭后确认各子窗口恢复独立尺寸；拉伸窗口观察同步缩放。

**Acceptance Scenarios**:

1. **Given** 网格模式已开启"保持相同宽高"，**When** 各子窗口原本尺寸不一，**Then** 重排后所有子窗口宽度一致、高度一致（差异 < 1px）
2. **Given** "保持相同宽高"已开启，**When** 用户关闭该开关，**Then** 各子窗口恢复为开启前的独立尺寸
3. **Given** "保持相同宽高"处于开启状态，**When** 用户拉伸窗口大小，**Then** 所有子窗口同步等比变化，且保持宽高一致

---

### User Story 5 - 统一布局设置入口与状态反馈 (Priority: P2)

提供统一的布局设置入口，打开后清晰展示当前排列模式、最大行数、最大列数、"保持相同宽高"开关的当前值；任何修改即时生效，无需额外确认。入口在子窗口被排列得杂乱无章时仍可一键到达。

**Why this priority**: 布局管理需要一个可发现的入口，否则前三项能力无法被用户触达；入口形式可与排列模式切换合并交付，故列 P2。

**Independent Test**: 通过菜单/工具栏打开布局设置，逐项修改并观察立即生效；在子窗口排列混乱状态下验证入口可达。

**Acceptance Scenarios**:

1. **Given** 任意排列状态，**When** 用户通过布局设置入口打开设置界面，**Then** 界面以分段按钮组展示当前排列模式（网格/优先行排/优先列排），并显示最大行、最大列、"保持相同宽高"的当前值
2. **Given** 布局设置界面已打开，**When** 用户修改任意一项设置，**Then** 布局立即更新，无需额外点击确认
3. **Given** 深色或浅色主题任意其一，**When** 打开布局设置界面，**Then** 界面控件清晰可读，对话框采用与其他对话框一致的无边框自定义标题栏（图标+标题+关闭按钮，可拖拽移动）

---

### User Story 6 - 子窗口最大化、全屏与隐藏/切换 (Priority: P2)

用户可将选中的子窗口**最大化**（放大占满整个中央区域，其余子窗口暂时隐藏），最大化时通过"向前切换/向后切换"按钮按顺序循环将其它子窗口设为最大化；用户也可点击"隐藏"按钮将子窗口从当前排列中隐藏（不销毁），并通过"视图 → 显示已隐藏的子窗口"恢复。**全屏**是中央区域级别的视图状态：通过"视图"菜单的"全屏"项开启后，中央区域扩展占满整个主窗口工作区（属性/数据/PyShell 面板临时隐藏）；若此时某子窗口已最大化，则该子窗口随之占满整个主界面。退出全屏/最大化后，原排列布局与面板显隐完整恢复。所有子窗口均不显示 Qt 自带的系统标题栏。子窗口标题栏按钮集：非最大化/非隐藏时显示"最大化 / 隐藏"；最大化时显示"还原 / 向前切换 / 向后切换"；"关闭"按钮始终显示（销毁该子窗口）；所有按钮等高等宽（统一尺寸）。单击子窗口任意区域（含标题栏）即选中该子窗口，子窗口边框始终为强调色，选中子窗口的边框加粗。

**Why this priority**: 最大化/全屏/隐藏依赖排列与选中能力，是布局之上的视图增强；用户明确要求，在核心排列能力（P1）之后交付。

**Independent Test**: 创建多个子窗口并选中其一，依次触发最大化、向前/向后切换、隐藏与恢复、全屏并截图比对覆盖范围；退出后验证布局与面板完整恢复。

**Acceptance Scenarios**:

1. **Given** 中央区域至少 2 个子窗口，**When** 用户对选中的子窗口触发最大化，**Then** 该子窗口放大占满整个中央区域，其余子窗口暂时隐藏，渲染内容与视图状态保留
2. **Given** 子窗口已处于最大化，**When** 用户退出最大化，**Then** 恢复最大化前的排列布局，各子窗口内容与视图状态一致
3. **Given** 子窗口已处于最大化，**When** 用户点击"向前切换/向后切换"，**Then** 最大化对象切换到上一/下一子窗口，原对象恢复为普通排列状态
4. **Given** 任意排列状态，**When** 用户点击子窗口标题栏的"隐藏"按钮，**Then** 该子窗口从排列中移除（不销毁），通过"视图 → 显示已隐藏的子窗口"可恢复
5. **Given** 任意排列状态，**When** 用户通过"视图"菜单开启"全屏"，**Then** 中央区域扩展占满整个主窗口工作区（属性/数据/PyShell 面板临时隐藏）
6. **Given** 全屏已开启，**When** 用户再次点击"全屏"或按 Esc 键，**Then** 属性/数据/PyShell 面板恢复显示，中央区域恢复原布局
7. **Given** 某子窗口已最大化（占满中央区域），**When** 用户开启全屏，**Then** 该子窗口随之占满整个主界面
8. **Given** 任意显示状态，**When** 用户查看任一子窗口，**Then** 子窗口不显示 Qt 自带的系统标题栏（无系统窗口装饰）

### User Story 7 - 面板外边框与内部边框：随主题适配 (Priority: P2)

数据集、属性、PyShell 三个可停靠面板均显示与当前主题匹配的独立边框：外边框 2px 主题边框色（深色主题浅灰、浅色主题深灰）；面板内部标题栏底部分隔线与内容子区域（数据树/属性网格/PyShell 输入输出区）间加 1px 主题边框色分隔线。主题切换后面板边框颜色自动更新，无需重启。

**Why this priority**: 面板边框属于界面视觉一致性改造，复用现有 QSS 主题体系（@border@ token）；不影响布局排列核心逻辑，故列 P2 与主题适配一并交付。

**Independent Test**: 在深色与浅色主题下分别截图比对三个面板的 2px 外边框与 1px 内部分隔线；切换主题后确认边框颜色自动更新、无旧色残留。

**Acceptance Scenarios**:

1. **Given** 深色主题，**When** 查看数据集/属性/PyShell 任一面板，**Then** 面板显示清晰可见的 2px 独立外边框，颜色为当前主题边框色（浅灰色系）
2. **Given** 浅色主题，**When** 查看同一面板，**Then** 外边框颜色自动切换为当前主题边框色（深灰色系），无需重启程序
3. **Given** 任意主题，**When** 查看面板内部，**Then** 标题栏底部分隔线与内容子区域（数据树/属性网格/PyShell 输入输出区）间均显示 1px 主题边框色分隔线
4. **Given** 主题切换已完成，**When** 检查面板边框颜色，**Then** 无残留旧主题颜色

### Edge Cases

- 子窗口数量为 0 或 1 时：三种模式均正常呈现，不报错（单子窗口铺满中央区域可用范围）
- 子窗口数量超过"最大行 × 最大列"容量时：超出子窗口不丢失、不崩溃、不遮挡，保持可访问
- 窗口尺寸过小导致网格放不下时：优先保证子窗口最小可用尺寸，必要时出现滚动，不将子窗口压缩至不可读
- 约束输入为 0、负数或非数字时：给出明确提示并恢复上次有效值
- 切换排列模式时：子窗口渲染内容与视图状态（缩放、视角、选中数据、滚动位置）不丢失
- 子窗口内为图形/曲线等渲染内容时：开启"保持相同宽高"后内容按比例缩放，不裁切、不变形
- 高 DPI（150%/200%）切换后：布局不错位，子窗口边界与控件保持清晰
- 布局管理仅作用于中央区域子窗口：侧边/底部可停靠面板（属性、数据、PyShell）的布局配置与显隐不受影响（全屏视图状态除外，退出后恢复）
- Python 命令创建时参数非法（如空名称、重复名称、非法类型）：给出明确错误提示，程序不崩溃
- 连续创建大量子窗口（如 20 个以上）：布局仍能正确排列，无明显性能劣化与卡顿
- 最大化/全屏进入与退出时：子窗口渲染内容与视图状态（缩放、视角、选中数据）不丢失，程序不崩溃
- 最大化/全屏期间调整布局设置或切换排列模式：行为一致、不崩溃，退出后布局正确恢复
- "保持相同宽高"开启时：子窗口间间隙仍然保持，且不破坏宽高一致性
- 单子窗口时：铺满可用范围，不因间隙产生多余留白
- 主题切换时：数据集/属性/PyShell 三个面板的外边框（2px）与内部 1px 分隔线颜色随主题自动更新，不残留旧主题颜色
- MainWindow 拆分时头文件组织：按功能域组织头文件，避免循环依赖（如 Dock 拖拽辅助类与 MainWindow 相互引用时以接口最小化处理）
- MainWindow 拆分时静态辅助元素（kFileDockObjectName 等常量、匿名命名空间工具函数）：随对应功能域移动，命名与注释保留，不改变可见行为

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持在 PyShell 中通过 Python 命令创建新的渲染子窗口，创建后子窗口立即出现在中央区域并参与当前布局排列
- **FR-002**: 系统 MUST 支持通过主窗口菜单栏创建新的渲染子窗口；菜单入口 MUST 触发同一 `create_window` Python 命令执行（禁止绕过命令层直接调用 C++ 入口），命令文本在 PyShell 回显、返回值打印，创建行为与 Python 命令一致
- **FR-003**: 新创建的子窗口内部为占位渲染视图（图形/曲线内容由后续功能接入），无内容时不报错、不崩溃
- **FR-004**: 系统 MUST 提供"优先行排"排列模式（By Row）：子窗口按行优先填充。未设置最大行/列数时保持比例网格：列数 = round(√n)、行数 = ⌈n/cols⌉（1→1×1、2→2×1、3→2×2、5→3×2、12→4×3、13→4×4）；设置最大行数时行数 = min(n, maxRows)、列数 = ⌈n/rows⌉；设置最大列数时列数 = min(n, maxCols)、行数 = ⌈n/cols⌉
- **FR-005**: 系统 MUST 提供"优先列排"排列模式（By Column）：子窗口按列优先填充，为优先行网格的转置。未设置最大行/列数时保持比例网格：行数 = round(√n)、列数 = ⌈n/rows⌉（1→1×1、2→1×2、3→2×2、5→2×3、12→3×4、13→4×4）；设置最大列数时列数 = min(n, maxCols)、行数 = ⌈n/cols⌉；设置最大行数时行数 = min(n, maxRows)、列数 = ⌈n/rows⌉
- **FR-006**: 系统 MUST 提供"网格"排列模式（Grid）：默认按行优先比例网格排列（同 FR-004 无约束情形）；MUST 支持用户设置优先行/优先列（Grid 填充方向，2026-08-29 反馈），设优先列时无约束网格转置（同 FR-005 无约束情形）；仅设置最大列数时列数受限、行自适应；仅设置最大行数时行数受限、列自适应；同时设置时列数 ≤ maxCols 固定、行数 = ⌈n/cols⌉ 继续增长
- **FR-007**: 系统 MUST 允许用户设置最大列数（1–10 整数）；网格模式下列数受限，行自适应换行，任何一行不超过该列数
- **FR-008**: 系统 MUST 允许用户设置最大行数（1–10 整数）；网格/优先行排模式下最多 row 行的约束生效
- **FR-009**: 系统 MUST 提供"保持相同宽高"开关；开启后同一排列中所有子窗口宽度与高度统一，且随窗口缩放同步等比变化；未开启时，排列末尾剩余空间被最后一个子窗口占满（从其位置延伸至网格右下角）
- **FR-010**: 系统 MUST 在关闭"保持相同宽高"后恢复各子窗口开启前的独立尺寸
- **FR-011**: 系统 MUST 提供统一的布局设置入口：排列模式以分段按钮组展示（网格/优先行排/优先列排，点击即切换，修改即时生效），并展示最大行、最大列、"保持相同宽高"取值与优先行/优先列方向（radio 组，仅网格模式显示，2026-08-29 反馈）；约束字段按模式显隐（网格显示行+列+方向，优先行排仅显行，优先列排仅显列）；对话框采用与其他对话框一致的无边框自定义标题栏（图标+标题+关闭按钮，可拖拽移动）
- **FR-012**: 系统 MUST 对非法约束输入（0、负数、非数字）给出明确提示，并恢复上次有效值
- **FR-013**: 系统 MUST 保证在任意排列模式与约束组合下，已打开子窗口的渲染内容与视图状态不丢失、程序不崩溃
- **FR-014**: 系统 MUST 保证子窗口数量超过最大行×最大列容量时，超出容量的子窗口保持可访问，不丢失、不遮挡
- **FR-015**: 系统 MUST 在排列子窗口时于相邻子窗口之间保留一致的间隙；子窗口须具有独立边框使边界清晰可辨，边框始终使用强调色（accent），选中子窗口的边框加粗
- **FR-016**: 系统 MUST 支持将选中子窗口**最大化**：放大占满整个中央区域可用范围，其余子窗口暂时隐藏；退出最大化后恢复原排列布局
- **FR-017**: 系统 MUST 支持**全屏**模式：中央区域（子窗口容器）扩展占满整个主窗口工作区（含侧边/底部可停靠面板区域，临时隐藏）；触发入口为"视图"菜单的"全屏"项（侧边栏不提供全屏按钮），与子窗口最大化正交：若某子窗口已处于最大化（占满中央区域），全屏时该子窗口随之占满整个主界面；退出全屏后按记录恢复各 Dock 显隐
- **FR-018**: 系统 MUST 保证子窗口不显示 Qt 自带的系统标题栏（无系统窗口装饰）
- **FR-019**: 系统 MUST 保证最大化/全屏的进入与退出不丢失子窗口的渲染内容与视图状态（缩放、视角、选中数据）
- **FR-020**: 系统 MUST 在子窗口标题栏提供"隐藏"按钮（与"最大化"按钮互斥显示状态），将选中子窗口从排列中隐藏（不销毁），可通过"视图 → 显示已隐藏的子窗口"恢复
- **FR-021**: 系统 MUST 在最大化子窗口的标题栏提供"向前切换/向后切换"按钮，按视图子窗口列表循环切换最大化对象
- **FR-022**: 系统 MUST 在子窗口标题栏提供"关闭"按钮（任何状态下均显示），点击后销毁该子窗口并从排列中移除（与"隐藏"不同：隐藏可恢复，关闭不可恢复）
- **FR-023**: 系统 MUST 为数据集、属性、PyShell 三个可停靠面板提供独立外边框：宽度 2px，颜色为当前主题边框色（@border@，深色主题浅灰、浅色主题深灰），随主题切换自动更新
- **FR-024**: 系统 MUST 为上述三个面板提供内部边框：标题栏底部分隔线及面板内内容子区域（数据树/属性网格/PyShell 输入输出区）之间的分隔线，宽度 1px，颜色为当前主题边框色（@border@）
- **FR-025**: 系统 MUST 将 MainWindow 逻辑按功能域拆分：辅助类（DockTitleBar、DockDragOverlay、SashHighlight、NoFocusRectDockStyle、FramelessDialog、ThemedFileDialog 等）移出为独立 .h/.cpp；MainWindow 成员函数分散到多个 .cpp（Dock 布局与拖拽/中央区子窗口/日志/文件/主题/标题栏与窗口控制/菜单动作工具栏）；MainWindow 类对外接口与用户可见行为不变（纯重构，无功能增删）
- **FR-026**: 系统 MUST 保证拆分后 MainWindow.cpp 不超过 400 行，其余文件按功能域自然划分且单文件不超过 400 行；构建配置（CMakeLists）同步更新，完整构建与现有测试全部通过
- **FR-027**: 系统 MUST 在每次创建子窗口时（无论经 PyShell 命令还是菜单栏入口），将所执行的 `create_window` 命令文本回显到 PyShell 输出区，并将其返回值（新建子窗口的 id 字符串，如 `'Plot_1'`）打印到 PyShell 输出区

### Key Entities *(include if feature involves data)*

- **渲染子窗口（Render Subwindow）**: 主窗口中央区域内用于渲染图形、曲线等可视化内容的视图子窗口（未来会有多个）。每个子窗口具有唯一标识、渲染内容引用、可见性状态、选中状态、尺寸偏好与视图状态（缩放、视角、选中数据）；不显示系统标题栏；创建统一经 Python 命令层执行（PyShell 命令与菜单栏入口均触发同一 `create_window` 命令行，命令文本回显、返回值打印）

## Assumptions

- "子窗口"指主窗口中央区域内用于渲染各种图形/曲线的视图子窗口；**不含**属性面板、数据面板、PyShell 窗口等侧边/底部可停靠面板，也不含独立弹出的对话框与外部窗口
- 布局管理（排列/约束/宽高）不改变侧边/底部可停靠面板的布局配置与显隐状态；全屏视图状态除外（临时隐藏面板，退出后恢复）
- 本次交付包含子窗口创建能力：创建统一经 Python 命令层（`create_window`）执行，PyShell 命令与主窗口菜单栏入口均触发同一命令行，命令文本在 PyShell 回显、返回值打印（见 Clarifications 会话）；子窗口内部的图形/曲线渲染内容由后续图形/曲线渲染功能接入，本次新子窗口显示占位内容
- 布局管理（排列模式、最大行/最大列、"保持相同宽高"）仅通过布局设置界面操作，**不提供** Python 命令/脚本接口；PyShell 中的 Python 命令仅用于创建子窗口
- "最大行/最大列"语义为网格布局的**上限约束**：子窗口数超过容量时自动换行/换列，超出容量的子窗口保持可访问；非固定行列数的强制网格
- 最大行/最大列的取值区间为 1–10 的整数；非法输入回退上次有效值
- "保持相同宽高"以均分可用区域为基准，各子窗口取一致尺寸；含图形/曲线渲染内容的子窗口按比例缩放
- 布局设置在当前会话内生效；v1 不做布局持久化，程序重启后恢复默认布局
