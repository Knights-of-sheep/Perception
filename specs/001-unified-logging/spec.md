# Feature Specification: 日志统一管理模块（后端基础设施）

**Feature Branch**: `001-unified-logging`

**Created**: 2026-08-23

**Status**: Draft

**Input**: User description: "统一的日志管理模块，C++ 与 Python 命令层共享同一日志流，支持文件轮转与控制台输出"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 通过统一 API 记录日志并即时可见 (Priority: P1)

开发者在应用任意模块（C++ 层）通过统一的日志 API 写入日志，日志同时输出到控制台与日志文件。这是全功能日志体系的最小可用闭环：开发者写完日志调用即可在开发控制台立即看到输出，无需额外配置。

**Why this priority**: 这是日志系统的地基——统一 API 决定后续所有能力（轮转、过滤、Python 汇入）的挂载点。没有它，其余需求无从谈起。

**Independent Test**: 编写一段调用统一日志 API 的 C++ 代码（如 `Logger::instance().info("hello")`），运行应用后可在开发控制台看到格式化输出，且日志文件中出现同一条记录。

**Acceptance Scenarios**:

1. **Given** 应用已启动且默认配置生效，**When** 任意模块调用统一日志 API 写入一条 INFO 日志，**Then** 该日志立即出现在开发控制台，且包含时间戳、日志级别、来源模块、消息正文。
2. **Given** 控制台已输出若干日志，**When** 日志级别低于当前阈值（默认 INFO）被写入，**Then** 控制台不显示该条记录，但文件仍按级别策略记录。
3. **Given** 日志 API 被多线程并发调用，**When** 同时写入多条日志，**Then** 每条记录完整、无交错截断，时间顺序可依赖（线程安全）。

---

### User Story 2 - 日志文件按大小轮转，保留可预期的归档 (Priority: P2)

应用持续运行产生日志，单文件达到 5MB 时自动轮转，仅保留最近 3 份归档，磁盘占用可预期，不会无限增长。

**Why this priority**: 长期运行的桌面应用必须有可预期的磁盘占用；轮转是日志文件管理的最小必要能力，且独立于日志 API 本身。

**Independent Test**: 将轮转阈值临时调小（如 1KB）并写入超过阈值的日志，观察产生 `xxx.log`、`xxx.log.1`、`xxx.log.2`、`xxx.log.3` 归档；继续写入后最旧归档被删除，文件总数不超过 4（1 当前 + 3 归档）。

**Acceptance Scenarios**:

1. **Given** 当前日志文件已达到 5MB，**When** 写入下一条日志，**Then** 当前文件被轮转为归档，新内容写入新文件。
2. **Given** 已有 3 份归档，**When** 再次触发轮转，**Then** 最旧归档被删除，归档数量保持在 3。
3. **Given** 日志文件路径已配置为应用数据目录，**When** 应用重启，**Then** 日志继续追加到原有文件（不覆盖历史），轮转状态正确恢复。

---

### User Story 3 - Python 命令层日志汇入统一日志流 (Priority: P2)

Python 命令层（`perception_py`，pybind11）产生的日志（含 `logging` 模块输出）与 C++ 日志汇入同一入口、同一文件，遵守同一级别与格式策略，实现"单一脚本化 API"精神下的日志一致性。

**Why this priority**: 命令层是用户交互主路径，其日志若独立于 C++ 日志流，将造成排查断裂与格式割裂；汇入统一流是打通 C++/Python 的诊断闭环。

**Independent Test**: 在 Python 命令层执行一个产生日志的调用（如自定义异常或 info 输出），观察该记录与 C++ 日志出现在同一文件，格式一致（时间戳/级别/来源标识 Python 来源）。

**Acceptance Scenarios**:

1. **Given** Python 命令层通过 `logging` 模块输出日志，**When** 调用触发，**Then** 该记录进入统一日志文件，级别与格式与 C++ 日志一致。
2. **Given** Python 侧写入 ERROR 级日志，**When** 日志写入，**Then** 控制台同步显示错误（级别阈值允许时）。
3. **Given** C++ 与 Python 在相近时间写入日志，**When** 查看日志文件，**Then** 两条记录按时间顺序排列，无格式错乱。

---

### Edge Cases

- 日志路径不可写（磁盘满、权限不足、目录不存在）时：写入失败不应崩溃应用，应降级为仅控制台输出并给出一次告警，不重复刷屏。
- 多线程/多进程（如 Python 与 C++ 同进程不同线程）同时写入同一文件：单条记录必须原子写入，不允许半行交错。
- 轮转触发瞬间有新写入：不得出现文件句柄泄漏或记录丢失。
- 日志消息含非 ASCII 字符（中文等）：统一按 UTF-8 编码，读写一致无乱码。
- 日志目录被外部删除后应用继续运行：应能重建目录继续写入。
- 超长单条消息：应完整写入或明确截断（带截断标记），不破坏后续记录格式。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供统一日志 API（C++ 静态访问入口，如 `Logger::instance()`），支持 INFO/DEBUG/WARN/ERROR/FATAL 级别写入。
- **FR-002**: 系统 MUST 支持日志级别阈值配置（默认 INFO），低于阈值的记录不输出到控制台；文件侧按同一阈值过滤。
- **FR-003**: 系统 MUST 以统一格式输出每条日志：时间戳（本地时间，毫秒精度）、日志级别、来源模块（含 C++ 文件/行或 Python 来源标识）、消息正文，UTF-8 编码。
- **FR-004**: 系统 MUST 支持日志文件路径配置（默认应用数据目录），目录不存在时自动创建，应用重启后追加写入不覆盖。
- **FR-005**: 系统 MUST 按大小轮转日志文件：单文件满 5MB 轮转，保留最近 3 份归档（`app.log`、`app.log.1`、`app.log.2`、`app.log.3`），超出删除最旧。
- **FR-006**: 系统 MUST 将日志实时输出到开发控制台（与错误提示共用同一输出通道），级别阈值满足即显示。
- **FR-007**: 系统 MUST 保证多线程写入线程安全：单条记录原子落盘，无交错截断。
- **FR-008**: 系统 MUST 将 Python 命令层（`perception_py`）产生的日志汇入统一日志流：同一文件、同一级别与格式策略；提供 Python 侧接入机制（logging handler 桥接）。
- **FR-009**: 系统 MUST 在日志写入失败（如路径不可写）时降级为仅控制台输出并告警，不崩溃应用。

### Key Entities *(include if feature involves data)*

- **LogRecord**: 单条日志记录。属性：时间戳、级别（DEBUG/INFO/WARN/ERROR/FATAL）、来源（模块名/C++ 文件行或 Python 来源）、消息正文。无实现细节，仅数据契约。
- **LogSink**: 日志输出目标。本期含两类：ConsoleSink（开发控制台）、FileSink（轮转文件）。统一 API 向所有已注册 sink 广播记录。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 任意模块通过统一 API 写入的日志在控制台与文件两侧均可见，格式字段齐全（时间戳/级别/来源/消息），单条记录 100% 完整写入。
- **SC-002**: 连续写入超过 5MB 日志后，文件侧自动轮转，归档数量稳定为 3 份，磁盘占用 ≤ 当前文件 + 3 归档。
- **SC-003**: 并发 8 线程 × 1000 条日志写入，无交错、无丢失，记录总数精确等于写入总数。
- **SC-004**: Python 命令层产生的日志与 C++ 日志同文件、同格式，时间顺序正确，无乱码（含中文消息）。
- **SC-005**: 日志路径不可用时应用正常运行，仅控制台输出并单次告警，无崩溃、无重复刷屏。

## Assumptions

- 日志默认路径为应用数据目录（随平台约定，如 Windows `%APPDATA%`），可通过配置覆盖。
- 默认日志级别为 INFO；级别配置全局生效（控制台与文件一致）。
- 本期范围仅后端基础设施：应用内日志查看/过滤 UI 面板明确**不在本期**，作为后续独立功能。
- Python 命令层与 C++ 运行于同一进程（pybind11 嵌入式解释器），跨进程日志分发不在本期。
- 轮转策略固定为大小轮转（5MB × 3 份）；按日期轮转等其他策略不在本期。
- 依赖现有开发控制台输出通道（`PythonConsole` 控制台）作为 ConsoleSink 的承载，复用其已有的错误展示样式（如 ERROR 级红色高亮）。
