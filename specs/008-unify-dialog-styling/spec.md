# Feature Specification: 弹窗样式层次化统一

**Feature Branch**: `008-unify-dialog-styling`

**Created**: 2026-08-30

**Status**: Draft

**Input**: User description: "将当前所有的带有弹窗的功能进行优化，主要是优化弹窗样式，之前有优化过一次，当时要求是和主题匹配且各弹窗样式统一，标题栏样式更要统一，但是现在发现并没有和主题匹配，因为和主题颜色不能一样，不然弹窗在主界面前显示看着一点都不明显不突出。要求弹窗样式背景色要和主题匹配（有搭配感、层次感、舒适感）"

## Clarifications

### Session 2026-08-30

- Q: 用户提出对 layout settings 功能进行优化，一是弹窗界面和布局，二是「按行排 / 按列排」模式不生效问题。选择「按行排 / 按列排」时，子窗口应按什么规则排布？ → A: **按行排 = 全部子窗口 1×N 横向排成一行；按列排 = N×1 纵向排成一列；「网格」保持现有比例网格**（Option A；**后续再次澄清修订，见下条**）
- Q: 布局设置中「By Row / By Column」的排布方向？ → A（再次澄清，修订上条）: **按行排（By Row）= 一列多行 N×1（每个子窗口占一行）；按列排（By Column）= 一行多列 1×N（每个子窗口占一列）**；「网格」保持比例网格 + 优先级轴约束
- Q: 行优先/列优先、最大行数/最大列数的适用范围与显隐规则？ → A: **行优先、列优先、最大行数、最大列数仅针对网格模式**；行优先与列优先互斥；网格内「行优先」时仅显示最大列数 spinbox（隐藏最大行数）、「列优先」时仅显示最大行数 spinbox（隐藏最大列数，2026-08-30 二次修订：约束轴 = 生效轴，行优先 → 最大列数、列优先 → 最大行数）；行优先同时意味着**按行填充**（第一行从左到右填满再下一行，如 7 个 → 3+3+1）、列优先同时意味着**按列填充**（第一列从上到下填满再下一列，如 7 个 → 3+3+1 纵向，2026-08-30 再修订）
- Q: 布局设置弹窗「界面和布局」的优化方向？ → A: 选 **A+B+C**，另新增一项「间隙宽度」：① 排列模式从下拉框改为**分段按钮组**（Grid / By Row / By Column，点击即切换，落实 004 FR-011 原要求）；② 弹窗内增加**实时排列预览**（缩略示意当前子窗口排布，随配置即时更新）；③ 增加**「恢复默认」按钮**（一键恢复：网格 + 行优先 + 无约束 + 不保持相同宽高 + 默认间隙）；④ 新增**「间隙宽度」控件**（px，作用于三种模式相邻子窗口间距）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 弹窗悬浮可辨：打开弹窗时一眼即可区分与主界面 (Priority: P1)

用户打开任意弹窗（帮助、关于、打开文件、导出图片、布局设置、日志设置、警告/确认消息）时，弹窗区域的背景颜色与主界面背景明显不同，视觉上"浮"在主界面之上。用户无需聚焦、无需细看，余光即可感知弹窗边界，不会被误认为主界面的某个面板。

**Why this priority**: 这是用户反馈的核心痛点——当前弹窗背景与主界面背景完全一致，弹窗在主界面之前"隐身"，无法突出。这是本次优化的第一价值。

**Independent Test**: 在主界面正常显示状态下，依次打开全部弹窗类型，观察弹窗背景与主界面背景是否存在可感知差异，且所有弹窗类型表现一致。

**Acceptance Scenarios**:

1. **Given** 应用以深色主题运行且主界面正常显示，**When** 用户打开任一弹窗，**Then** 弹窗背景与主界面背景存在明显可感知的层次差异，弹窗边界清晰可辨
2. **Given** 应用以浅色主题运行，**When** 用户打开任一弹窗，**Then** 弹窗同样与主界面背景存在可感知层次差异（方向与深色主题相反但同样明确）
3. **Given** 任意主题下弹窗已打开，**When** 弹窗与主界面并排可见，**Then** 弹窗文字、控件均清晰可读，不受层次色变化影响

---

### User Story 2 - 弹窗随主题协调：切换主题后弹窗自动适配且配色舒适 (Priority: P2)

用户切换应用主题（深色/浅色/高对比）后，所有弹窗的背景、标题栏、文字、控件颜色自动随新主题变化，与主界面保持同一配色体系，呈现"搭配感"与"舒适感"，不出现某一块颜色孤立、刺眼或不协调的情况。

**Why this priority**: 弹窗颜色来自主题色板是宪法「无例外原则」的硬约束；层次差异必须建立在主题协调之上，否则层次感会变成"色差刺眼"。P2 依赖 P1 的弹窗背景层改造一并实现。

**Independent Test**: 依次切换所有内置主题，逐一打开各弹窗类型，检查弹窗与主界面配色是否协调、无孤立色块、无刺眼对比。

**Acceptance Scenarios**:

1. **Given** 用户处于任一主题，**When** 切换至另一主题，**Then** 已打开及随后打开的弹窗背景、标题栏、控件颜色全部自动跟随新主题，无需重启或手动刷新
2. **Given** 任一主题下弹窗打开，**When** 对照主界面面板色与弹窗背景色，**Then** 二者属于同一配色家族（色相/饱和度协调），仅亮度层次不同，无突兀配色
3. **Given** 高对比主题下，**When** 打开任一弹窗，**Then** 弹窗与主界面的层次区分与文字可读性均满足无障碍要求

---

### User Story 3 - 标题栏统一：所有弹窗标题栏外观一致 (Priority: P3)

所有弹窗的标题栏（应用图标 + 标题文字 + 关闭按钮）在高度、图标尺寸、字号、按钮位置、底部分隔线等外观上完全一致；用户面对任何弹窗都能立即认出"这是本应用的窗口"，标题栏可作为弹窗身份的视觉锚点。

**Why this priority**: 标题栏统一是 004 已确立并写入宪法的要求（FR-011），本次层次化改造不得破坏这一既有成果；将其列为独立验收项，防止改造过程中出现"背景变了、标题栏却漏改"的回归。

**Independent Test**: 并排打开帮助、关于、布局设置等弹窗，比对各自标题栏外观。

**Acceptance Scenarios**:

1. **Given** 任意主题下，**When** 并排打开至少三个不同类型的弹窗，**Then** 各弹窗标题栏高度、图标、标题字号、关闭按钮位置与底部分隔线视觉一致
2. **Given** 任一弹窗打开，**When** 点击其关闭按钮，**Then** 弹窗关闭且无残留（与主界面行为一致）
3. **Given** 任一弹窗打开，**When** 拖动其标题栏，**Then** 弹窗跟随移动（可拖拽性保持）

---

### User Story 4 - 布局设置弹窗优化：按行/按列真正生效 + 控件按模式显隐 + 界面升级 (Priority: P1)

用户打开「视图 → 布局设置…」，选择「按行排」时所有子窗口排为一列多行（N×1，每个子窗口占一行）、选择「按列排」时排为一行多列（1×N，每个子窗口占一列）、选择「网格」时按比例网格排布；三种模式切换后子窗口立即重排且视图状态不丢失。行优先/列优先与最大行/列约束仅存在于网格模式：行优先与列优先互斥，行优先时仅显示最大行数、列优先时仅显示最大列数，其余约束控件在对应模式下隐藏，弹窗界面整洁无歧义。弹窗本身以分段按钮组切换模式、提供实时排列预览与「恢复默认」按钮，并可设置子窗口间隙宽度。

**Why this priority**: 按行排/按列排当前与网格视觉无差异（无约束时同构、有约束时模式被忽略），用户反馈"不生效"；同时弹窗控件随模式显隐混乱（Grid 同时显示行+列+优先级）。本故事一次性解决语义与界面两个问题。

**Independent Test**: 打开 ≥3 个子窗口，依次切换按行排/按列排/网格并设置不同优先级与约束，截图比对排布结果与弹窗控件显隐；切换前后渲染内容与视图状态一致。

**Acceptance Scenarios**:

1. **Given** 中央区域至少 3 个子窗口已打开，**When** 用户选择「按行排」，**Then** 所有子窗口 N×1 排成一列多行、互不重叠、完整可见，弹窗内不显示最大行/最大列/优先级控件
2. **Given** 同上，**When** 用户选择「按列排」，**Then** 所有子窗口 1×N 排成一行多列，弹窗内不显示最大行/最大列/优先级控件
3. **Given** 用户选择「网格」，**When** 查看弹窗，**Then** 显示优先行/优先列 radio（互斥）且按所选优先级联动显示约束：行优先仅显示最大行数、列优先仅显示最大列数
4. **Given** 用户在任一子窗口内进行了操作（缩放、旋转视角、选中数据），**When** 在三种模式间切换，**Then** 子窗口立即重排且渲染内容与视图状态完整保留
5. **Given** 布局设置弹窗已打开，**When** 用户点击「网格 / 按行排 / 按列排」分段按钮，**Then** 模式即时切换（无需下拉菜单），弹窗与中央区域同步更新
6. **Given** 弹窗内任一配置变更，**When** 观察弹窗内的实时排列预览，**Then** 预览缩略示意随配置即时更新，与中央区域真实排布一致
7. **Given** 用户已修改多项配置，**When** 点击「恢复默认」，**Then** 弹窗所有控件回到默认值（网格 + 行优先 + 无约束 + 不保持相同宽高 + 默认间隙）且中央区域立即恢复默认排布
8. **Given** 用户在「间隙宽度」中输入 0–50 的数值，**When** 观察中央区域，**Then** 相邻子窗口间距按数值变化，三种模式均生效

---

### Edge Cases

- **浅色主题下的层次方向**：深色主题弹窗背景比主界面更亮、浅色主题应比主界面更深（保持"弹窗高一层"的恒定隐喻），且不得翻转成相反效果
- **高对比/无障碍主题**：层次差异不得以牺牲可读性为代价；文字与背景对比度始终达标
- **消息框（警告/确认）**：其标题栏、图标区、按钮区同样套用弹窗层次样式，不因"系统组件"属性而例外
- **极小/极大尺寸弹窗**：弹窗内容高度接近标题栏高度或占满屏幕时，背景层次、边框与标题栏仍完整呈现
- **多弹窗叠加**：连续打开多个弹窗时，每个弹窗相对其父级均保持同样的层次关系，不出现同级弹窗互相吞没
- **主题热切换时弹窗已打开**：切换主题瞬间，已打开弹窗的层次样式与标题栏同步更新，无残留旧色
- **按行排/按列排无约束控件**：两种模式下最大行/最大列/优先级控件整体隐藏，避免用户误以为可设置（2026-08-30 反馈）
- **网格内优先级联动显隐**：行优先↔列优先切换时最大行/最大列 spinbox 互斥显示（行优先 → 显示最大列数、列优先 → 显示最大行数，2026-08-30 二次修订），隐藏一侧的当前值保留但不参与布局计算（2026-08-30 反馈）
- **单子窗口边界**：按行排/按列排/网格在仅 1 个子窗口时均铺满可用范围，不产生额外内边距
- **间隙宽度边界**：间隙 0 时子窗口无缝相邻（边框仍分隔）；间隙 50 时子窗口仍完整可见、不溢出中央区域（2026-08-30 反馈）
- **恢复默认**：仅重置布局配置，不影响子窗口内容与视图状态（2026-08-30 反馈）
- **实时预览空态**：子窗口为 0 时预览显示空状态提示、为 1 时预览显示铺满形态（2026-08-30 反馈）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为所有应用弹窗（对话框、消息框、文件对话框）提供统一且与主界面背景不同的"弹窗背景层"，二者对比必须可被用户立即感知
- **FR-002**: 弹窗背景层 MUST 来源于主题色板（作为独立的语义色），随主题切换自动更新，禁止使用色板之外的硬编码颜色
- **FR-003**: 弹窗背景层 MUST 与主界面背景属于同一配色家族，仅亮度层次不同，呈现搭配感与舒适感（无孤立、刺眼色块）
- **FR-004**: 所有弹窗 MUST 保留统一的无边框自定义标题栏（图标 + 标题 + 关闭按钮，可拖拽移动），其高度、图标尺寸、标题字号、按钮位置、底部分隔线在各弹窗间视觉一致
- **FR-005**: 消息框（警告/确认类）MUST 同样采用无边框自定义标题栏与弹窗背景层，消除"系统标题栏/系统样式"例外（对齐宪法「技术栈约束 · GUI」）
- **FR-006**: 弹窗 MUST 具备清晰的视觉边界（如边框），配合背景层次共同形成"悬浮于主界面之上"的效果
- **FR-007**: 弹窗内控件（按钮、输入框、下拉框、列表等）MUST 继续使用主界面同款主题样式，仅背景层与主界面不同，不产生"弹窗内另一套主题"的分裂感
- **FR-008**: 系统 MUST 使「按行排」模式将所有子窗口排列为一列多行（N×1 纵向平铺，每个子窗口占一行）、「按列排」模式排列为一行多列（1×N 横向平铺，每个子窗口占一列）（2026-08-30 反馈修订；修订 004 FR-004/005 的比例网格语义）
- **FR-009**: 行优先、列优先、最大行数、最大列数 MUST 仅在网格模式生效；按行排/按列排模式下布局设置弹窗隐藏这些控件（2026-08-30 反馈）
- **FR-010**: 网格模式的优先行/优先列 MUST 互斥（radio 单选）；行优先时弹窗仅显示最大列数 spinbox、列优先时仅显示最大行数 spinbox，另一个自动隐藏（2026-08-30 反馈；二次修订：约束轴 = 生效轴，行优先 → 最大列数、列优先 → 最大行数）；优先级同时 MUST 决定网格填充方向：行优先按行填充（第一行从左到右填满再下一行）、列优先按列填充（第一列从上到下填满再下一列），弹窗实时预览与中央区域真实排布均随填充方向变化（2026-08-30 再修订）
- **FR-011**: 三种排列模式切换 MUST 立即重排中央区域子窗口且不丢失渲染内容与视图状态（2026-08-30 反馈）
- **FR-012**: 布局设置弹窗 MUST 以分段按钮组展示排列模式（Grid / By Row / By Column，点击即切换，修改即时生效），落实 004 FR-011 原要求（当前为下拉框，2026-08-30 反馈）
- **FR-013**: 布局设置弹窗 MUST 提供实时排列预览（缩略示意当前子窗口排布），随任一配置变更即时更新（2026-08-30 反馈）
- **FR-014**: 布局设置弹窗 MUST 提供「恢复默认」按钮，一键恢复默认配置（网格 + 行优先 + 无约束 + 不保持相同宽高 + 默认间隙）（2026-08-30 反馈）
- **FR-015**: 布局设置弹窗 MUST 提供「间隙宽度」控件（px，范围 0–50，默认与当前实现一致 = 6），作用于三种模式的相邻子窗口间距（2026-08-30 反馈）

### Key Entities

- **弹窗类型清单**：应用内全部弹窗的枚举（帮助、关于、打开文件、导出图片、导出命令、布局设置、设置日志路径、警告、确认），每类均须套用统一弹窗样式
- **弹窗背景层语义色**：主题色板中新增的弹窗层背景定义，与主窗口背景（L0）、面板背景（L1）形成明确的层级序列；不落地为具体实现细节，仅约束其"存在且随主题变化"
- **间隙宽度（spacing）**：布局配置中相邻子窗口间距（px），本 feature 由常量改为可配置（默认 6、范围 0–50，修订 004 data-model「常量、不对用户暴露」）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在任一内置主题下，弹窗背景与主界面背景的亮度差异均可被用户立即感知（目测对比度差异 ≥ 8%），用户无需聚焦即可分辨弹窗边界
- **SC-002**: 切换全部内置主题后，弹窗背景、标题栏、控件颜色 100% 随主题更新，且弹窗背景与主界面背景、文字三者对比度均满足可读性要求（无配色冲突）
- **SC-003**: 全部弹窗类型（≥ 5 类）的标题栏外观一致：高度、图标尺寸、标题字号、关闭按钮位置逐项一致，并排对比无肉眼差异
- **SC-004**: 5 名体验者中至少 4 名能在 1 秒内正确指出随机打开的弹窗边界（弹窗相对主界面的悬浮层次明确）
- **SC-005**: 弹窗样式改造不改变任何弹窗的功能行为（可打开、可关闭、可拖拽、操作结果与改造前一致），回归测试 100% 通过
- **SC-006**: 布局设置弹窗中按行排/按列排/网格三模式排布结果互不相同且符合各自定义（N×1 / 1×N / 比例网格）；网格内优先级切换时约束控件显隐联动正确，控件显隐切换后弹窗布局不跳动；网格排布方向符合优先级：7 个子窗口行优先按行 3+3+1、列优先按列 3+3+1（纵向），弹窗预览与中央区域排布一致（2026-08-30 反馈 / 再修订）
- **SC-007**: 布局设置弹窗具备分段按钮组、实时预览、恢复默认、间隙宽度四项能力；任一配置变更后弹窗内预览与中央区域真实排布一致，恢复默认后配置回到默认值（2026-08-30 反馈）

## Assumptions

- 沿用既有共享标题栏工厂与主题令牌体系（004 FR-011 确立的无边框标题栏架构），本次为"样式层次化升级"而非"推倒重来"
- 深色主题下弹窗背景比主界面背景亮一档、浅色主题下深一档（参考 VS Code 对话框层级范式）；具体色值与投影/边框形态由实现层决定，spec 仅约束"层次可感知、配色协调"

- 范围仅限应用内弹窗；操作系统级与第三方对话框不在本次范围
- 主题色板新增弹窗背景层语义色后，主界面各背景层（窗口/面板/视图）色值保持现状不变，不因弹窗改造而连带调整

- 间隙宽度默认值采用当前实现值 6px（004 spec 记录的默认 4px 与代码现状不一致，以代码为准）
