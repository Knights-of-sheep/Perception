# Feature Specification: 文件类型支持目录（获取与生成）

**Feature Branch**: `009-supported-file-types`

**Created**: 2026-08-31

**Status**: Draft

**Input**: User description: "获取或者生成本程序以后要支持的所有文件类型"

## 背景

Perception 对标 ParaView 与 Synopsys SVisual。宪法「文件格式范围」已声明支持 VTK 全部类型、SVisual（.plt/.tdr）、HDF5（.h5/.hdf5）与曲线数据（.csv/.dat），但当前这些格式只散落在文件打开过滤字符串、图标映射与宪法条款中，缺乏一份完整、权威、可查询、可再生成的文件类型清单。本 feature 建立这份权威目录，并提供「获取」（运行时可查询）与「生成」（由目录派生过滤列表 / 图标映射 / 文档）两种能力，使程序**以后要支持的所有文件类型**拥有唯一事实来源，杜绝"文档说一套、程序里另一套"的漂移。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 权威文件类型目录 (Priority: P1)

用户（产品、研发、测试）需要一份完整、唯一、可信的文件类型清单：程序现在能打开什么、将来要支持什么，均出自同一份目录。查阅该目录即可回答"这个文件格式本程序支不支持、是现在支持还是以后支持"，且任何文档、打开过滤、图标映射都不与之矛盾。

**Why this priority**: 宪法要求"范围之外格式默认超范围，除非规范明确批准"；目录正是对"以后要支持的所有文件类型"的正式批准与单一事实来源，也是另外两条用户故事的前提。

**Independent Test**: 将目录与宪法「文件格式范围」逐条比对（VTK / SVisual / HDF5 / 曲线 4 个格式族全覆盖）；将目录中"已支持"条目与实际能打开的格式逐一比对，两者一一对应。

**Acceptance Scenarios**:

1. **Given** 我需要了解程序支持的文件类型，**When** 我查阅权威目录，**Then** 目录列出全部格式族（VTK / SVisual / HDF5 / 曲线），每个条目含扩展名、格式名称、数据种类与支持状态
2. **Given** 目录声明某格式为"已支持"，**When** 我用该扩展名的文件执行打开，**Then** 程序能识别并加载；"已支持"与实际可打开一一对应
3. **Given** 目录声明某格式为"规划中"，**When** 我在打开对话框中选中该扩展名的文件，**Then** 打开过滤列表仍展示它（供发现与核对），但程序按"不支持"给出清晰提示、不进入读取流程

---

### User Story 2 - 运行时可查询（获取） (Priority: P2)

程序运行期间，用户随时可以查询"程序支持哪些文件类型"，获得完整清单（扩展名、格式说明、数据种类、状态），用于判断同事/工具产出的数据文件（如 .tdr、.vtp）能否被本程序打开。

**Why this priority**: 半导体仿真工程师拿到外部产出的数据文件时，需要快速确认本程序能否打开；查询结果必须与权威目录一致，否则失去可信度。

**Independent Test**: 在运行中的程序内发起格式查询，核对返回清单与权威目录一致；用清单中"已支持"的扩展名打开文件验证可加载。

**Acceptance Scenarios**:

1. **Given** 程序正在运行，**When** 用户发起"查询支持的文件类型"，**Then** 1 秒内返回完整清单（扩展名 + 格式名称 + 数据种类 + 状态）
2. **Given** 清单返回某格式为"已支持"，**When** 用户尝试打开该格式文件，**Then** 打开成功；"规划中"格式打开时得到清晰的"不支持"提示，不进入读取流程
3. **Given** 权威目录内容发生变化，**When** 用户再次发起查询，**Then** 返回内容与最新目录一致，无需重启程序

---

### User Story 3 - 单一来源生成一致产物（生成） (Priority: P3)

文件打开对话框的格式过滤、文件类型图标映射、README / 文档中的格式清单，全部由权威目录派生；新增、移除或变更一种格式只改目录一处，其余产物自动同步，任何产物都不会出现"目录里没有的格式"或"目录里有但产物缺失"的情况。

**Why this priority**: 当前打开过滤是硬编码字符串，与图标映射、文档、读取能力各自为政、容易漂移；单一来源机制是保证长期一致性的根基，但其价值在格式数量增多后才充分体现，故列 P3。

**Independent Test**: 在目录中新增 / 移除一种格式并执行生成，检查打开过滤列表、图标映射、文档三处同步变化；人为制造不一致后执行一致性校验，确认能报告差异。

**Acceptance Scenarios**:

1. **Given** 目录中新增一种"已支持"格式，**When** 执行生成并打开文件对话框，**Then** 过滤列表包含该格式，文档表格也包含它
2. **Given** 目录中移除一种格式，**When** 执行生成，**Then** 打开过滤列表与文档中该格式同步消失
3. **Given** 目录与某处产物被人为改得不一致，**When** 执行一致性校验，**Then** 系统列出具体差异，不静默忽略

---

### Edge Cases

- **扩展名大小写**：`.PLT` 与 `.plt` 视为同一格式，匹配不区分大小写
- **无扩展名文件**：目录按扩展名无法匹配，需有明确的"未知格式"行为（内容嗅探不在本 spec 范围）
- **多用途扩展名**：`.dat` 在不同数据源可能表示曲线或结构数据，目录须能表达"多用途"
- **复合 / 并行格式**：`.vtm` / `.pvtu` 等包含多个子数据集的格式，目录仍按单一条目记录，不拆分为多条
- **"规划中"格式的暴露**：状态为"规划中"的格式出现在权威目录、文档与打开过滤列表（供用户在对话框内发现与核对程序将支持什么）；选中后按"不支持"给出清晰提示、不进入读取流程（避免无提示的静默失败）
- **目录与读取能力不一致**：新增读取能力忘记更新目录、或目录删除格式但读取能力仍在，均须可检测并报告
- **隐藏文件 / 特殊扩展名**：不匹配任何目录条目的文件按未知格式处理，给出统一提示
- **空目录场景**：目录为空或未初始化时，查询返回明确的空状态提示，不崩溃、不返回歧义结果

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 维护一份权威文件类型目录，作为程序支持格式的唯一事实来源
- **FR-002**: 目录 MUST 完整覆盖宪法「文件格式范围」声明的全部格式族：VTK（全部类型）、SVisual、HDF5、曲线数据
- **FR-003**: 目录中每个文件类型条目 MUST 包含：扩展名、格式名称、格式族、数据种类（曲线 / 结构 / 双用途）、支持状态（已支持 / 规划中）
- **FR-004**: 目录 MUST 区分「已支持」（当前可打开）与「规划中」（范围已批准、尚未实现）两种状态
- **FR-005**: 用户 MUST 能在程序运行期间查询完整文件类型清单（获取能力），返回结果与权威目录一致
- **FR-006**: 系统 MUST 能由目录生成文件打开对话框的格式过滤列表（生成能力），与目录保持同步
- **FR-007**: 系统 MUST 能由目录生成文件类型图标映射与文档中的格式清单（生成能力），与目录保持同步
- **FR-008**: 「已支持」条目 MUST 与程序实际可打开的格式一一对应
- **FR-009**: 打开过滤列表 MUST 覆盖权威目录全部条目（含「规划中」，供发现与核对）；「规划中」条目 MUST 在打开时按「不支持」给出清晰提示、不进入读取流程（产品裁决：展示全部、打开拦截）
- **FR-010**: 扩展名匹配 MUST 大小写不敏感
- **FR-011**: 系统 MUST 能检测目录与实际读取能力之间的差异，并以可读形式报告（差异清单，不静默）
- **FR-012**: 目录 MUST 支持同一扩展名标记多种数据用途（如 `.dat` 的曲线 / 结构双用途）

### Key Entities *(include if feature involves data)*

- **文件类型条目（File Type Entry）**: 权威目录的一行，属性为扩展名、格式名称、格式族、数据种类、支持状态；代表"一种程序可能打开的文件类型"
- **格式族（Format Family）**: 条目的分组维度（VTK 遗留 / VTK XML / SVisual / HDF5 / 曲线），用于文档组织与过滤分组
- **支持状态（Support Status）**: 已支持（有读取能力）/ 规划中（范围已批准、未实现）
- **派生产物（Derived Artifacts）**: 由目录生成的打开过滤列表、图标映射、文档表格；不是独立事实源，是目录的可消费视图

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 权威目录完整覆盖宪法「文件格式范围」的 4 个格式族（VTK / SVisual / HDF5 / 曲线），逐条与宪法比对无遗漏
- **SC-002**: 「已支持」条目与程序实际可打开格式 100% 一一对应（无"目录有而不可打开"、亦无"目录无但可打开"）
- **SC-003**: 由目录生成的打开过滤列表与目录 100% 一致；新增 / 移除格式后重新生成，过滤列表同步变化
- **SC-004**: 用户在运行中的程序内发起格式查询，100% 情况下 1 秒内获得完整清单
- **SC-005**: 变更一种格式的目录条目（≥1 次新增 + ≥1 次状态变更），全部派生产物同步更新，无需任何二次手工修改
- **SC-006**: 人为构造目录与读取能力不一致的场景，100% 能被检测并报告具体差异

## Assumptions

- 目录边界以宪法「文件格式范围」为准：VTK 全部类型、SVisual、HDF5、曲线；本 feature 默认不新增宪法之外的格式族（如需新增，走「修改宪法」或另行 spec 批准）
- VTK「全部类型」具体化为：遗留 `.vtk`；XML 数据格式 `.vti/.vtp/.vtu/.vts/.vtr`；复合与并行变体（`.vtm/.vtmb/.vth/.vto`、`.pv*` 系列与 `.pvd`）计入"规划中"范围，具体实现优先级由后续 feature 决定
- 「获取」的实现入口遵循命令驱动架构（程序内命令查询，符合宪法对数据处理操作经命令层的要求）；「生成」覆盖打开过滤、图标映射、文档清单三类产物
- `.dat` 扩展名在不同数据源可能表示曲线或结构数据，目录按「多用途」标注，具体识别规则在读取器实现时确定
- 无扩展名文件的内容嗅探不在本 spec 范围；未知格式给出清晰"不支持"提示即可
- 本 feature 只建立目录与获取 / 生成能力，**不实现**各「规划中」格式的读取器（那是后续独立 feature 的范围）
- 文件打开对话框的过滤列表与图标映射表现，自本 feature 起以目录生成为准
